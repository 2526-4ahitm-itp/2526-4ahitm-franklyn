The low-risk baseline: one list, four filter chips, support content in the side region.

Notes

  • One centred container. Header, list and widgets all sit inside the same capped block; only the header rule spans the viewport. The widget column is part of main, not a separate region hanging off its side.
  • PIN is a plain integer, drawn from the configured range (1337–4200 by default, franklyn.pin.min / .max). Four digits, no grouping, no separator.
  • Card is four slots: PIN · title · one state-dependent secondary · state. Secondary carries connected count when live, start time when scheduled, duration when finished. An optional room shares that slot.
  • No actions on cards and no load-more button. The strip at the bottom is the observer target — it is what the teacher sees for the fraction of a second before the next page lands.
  • Last-exam block turns the side region into a debrief surface: planned versus actual runtime, joins, recordings, dropouts, gaps. This is where post-exam stats grow.
  • Trade-off. Past exams are only reachable through a chip or search. Fine for a term, weak after two years.

Fork A of the spine. Today is a bounded band; the future stacks above it, history below.

Notes

  • The now problem, solved by widening it. A line between two cards implies now falls in a gap, which is wrong while an exam is running. A band says "this region is today" — the live exam sits inside it, which is true for the whole 90 minutes it runs.
  • NEXT UP lives inside the band, between today's exams, so it reads as a position in the day rather than a separate widget. It only appears when another exam follows today.
  • The band is always present, even on a day with no exams — then it reads "TODAY · NO EXAMS" and stays the scroll anchor. Removing it would make the page lose its landmark exactly when the teacher is least oriented.
  • The band breaks the gutter on purpose: it is a region, not an event, so it does not get a time label or a node on the axis.
  • Scrolling. Both ends are observer targets, so history and future page in as you move. Because the view opens anchored on the band rather than at the top of a document, this wants a scripted scroll position rather than the native one — the same mechanism makes "jump to date" work.
  • Trade-off. Two reading directions remain unusual, and the band is a third kind of container next to the card and the row.

Fork B of the spine. Same timeline, but today is drawn to scale instead of as a list.

Notes

  • The other answer to the now problem. Fork A widened now into a region; this one gives the axis a scale so a point marker is legitimate. The 09:42 tick cuts through the live exam block, which is exactly what is happening.
  • Duration becomes visible without being written down: a 90-minute exam is a tall block, a 45-minute one is short. Overlapping or back-to-back exams are obvious at a glance — a planning signal the list form cannot give.
  • NEXT UP moves into the day header because the block below already shows where it sits in the day. Saying it twice would be noise.
  • Other days stay as rows. Only today earns a scale; drawing every day to scale would make the page mostly empty hours.
  • Where it needs work: the rail window has to be derived (first exam minus an hour to last exam plus an hour, clamped to a school day), empty days collapse the rail to a single line, and an exam running past the window needs a cut-off marker.
  • Trade-off versus fork A. More truthful, more layout machinery, and worse on a day with one short exam — a tall mostly-empty rail for a single 25-minute block.

A week navigator scopes the list. Past and future are the same gesture: step the strip.

Notes

  • Time-window scoping, not filtering. No Upcoming / Finished chips, because the window already decides. Last month is four steps back or one click in the side calendar.
  • Empty days are gone from the list. The strip already shows Wed, Fri and the weekend as dotless, so repeating "no exams" below was duplicate information.
  • Today's group is labelled rather than fenced. This layout does not need a now marker: the strip highlights the day, and a one-day window is short enough that position in the day is obvious from the times.
  • Outside-this-week block prevents tunnel vision — the next exam beyond the window stays visible, so stepping through empty weeks is never necessary.
  • Search behaves differently here. The timeline layouts filter in place, which this one cannot do without destroying the week window. Instead the field opens a dropdown of small result cards over the page, like a search suggestion list — picking one moves the strip to that exam's week.
  • Trade-off. Worst option for browsing a large archive; best for the weekly rhythm a school actually runs on.

Summary

Four layouts, one card component. The two spine forks differ only in how today is drawn.

The fork

Both spines fix the same problem. Option 2 widens now into a region, so the live exam is inside it for as long as it runs. Option 3 gives today an hour scale, so a point marker becomes truthful and duration becomes visible. Option 2 is cheaper and never looks wrong; Option 3 is more informative but degrades on a thin day — a tall rail holding one short block.

They are not exclusive. The band in Option 2 could expand into the rail from Option 3 on demand, which would give the default the calm of a list and the detail of a schedule on request.

Shared across all four

One card (PIN · title · one state-dependent secondary · state, no actions), one primary action block, one side region, one width rule shared by the header and the body, observer sentinels instead of load-more buttons. Everything is driven by custom properties in styles.css. Radii, shadows and decorative strokes are deliberately absent.

Settled while reviewing

Empty state is the list itself with a placeholder in it — "Nothing here yet, schedule an exam!" — not a separate illustrated screen. Search filters in place in the three timeline and list layouts; in Week Strip it opens a dropdown of small result cards instead, because filtering in place would break the week window. Connection and error states are out of scope here: the frontend only displays what server and sentinel report.

Open items

Lifecycle is still SCHEDULED / LIVE / FINISHED. If LIVE later splits into preparation and running, it changes the state slot and the secondary slot, nothing else. Room is optional and shares the secondary slot. Planned-versus-actual duration in the last-exam block needs startTime/endTime against startedAt/endedAt; dropouts and gaps are not modelled on the server yet.
